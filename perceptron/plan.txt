

```markdown
You are an expert Full-Stack Machine Learning Engineer, Pedagogical Educator, and UI/UX Designer. 

Your objective is to generate a complete, production-grade, interactive web application and documentation that demonstrates the **Perceptron Learning Rule** (based on Chapter 4 of Martin T. Hagan's *Neural Network Design*) through a real-world 2D scenario: **"Student Exam Pass/Fail Predictor"**.

---

### Project Specification & Problem Formulation
- **Scenario:** Classifying whether a student will Pass or Fail an exam.
- **Input Features ($p \in \mathbb{R}^2$):**
  - $p_1$: Study Hours per week (Range: $0$ to $10$).
    - $p_2$: Class Attendance percentage (Normalized range: $0$ to $10$, where $10 = 100\%$).
    - **Target ($t$):**
      - $t = 1$: Pass (Rendered in Green / Class 1).
        - $t = 0$: Fail (Rendered in Red / Class 0).
        - **Mathematical Framework (Hagan Ch. 4,present in the folder: "C:\Users\User\machine_learning\perceptron\Neural Network Design Hagan-72-104.pdf"):**
          - Activation: $a = \text{hardlim}(n) = \text{hardlim}(w_1 p_1 + w_2 p_2 + b)$, where $\text{hardlim}(n) = 1$ if $n \ge 0$, else $0$.
            - Error: $e = t - a$.
              - Unified Weight Update: $W^{\text{new}} = W^{\text{old}} + e p^T$.
                - Bias Update: $b^{\text{new}} = b^{\text{old}} + e$.
                  - Decision Boundary: $w_1 p_1 + w_2 p_2 + b = 0 \implies p_2 = -\frac{w_1}{w_2}p_1 - \frac{b}{w_2}$.

                  ---

                  ### Implementation Requirements

                  You must provide the full, runnable codebase with **zero placeholders, no `// TODO` comments, and no truncated code snippets**. Organize the project into the following directory structure:

                  ```text
                  student_perceptron_app/
                  ├── perceptron.py          # Core Perceptron algorithm implementation in Python
                  ├── app.py                 # Lightweight Backend server (Flask) exposing REST API
                  ├── templates/
                  │   └── index.html         # Frontend interface with HTML5 Canvas & HCI controls
                  ├── static/
                  │   ├── style.css          # Responsive CSS styling & intuitive layout
                  │   └── script.js          # Canvas rendering, mouse interactions, & API integration
                  └── report.md              # Exhaustive technical and non-technical documentation

                  ```

                  ---

                  ### Detailed File Deliverables

                  #### 1. `perceptron.py`

                  * Create a clean `Perceptron` class implemented with Python and NumPy.
                  * Implement methods:
                  * `__init__(self, input_dim=2, learning_rate=1.0)`: Initialize weights and bias randomly or to zero.
                  * `predict(self, p)`: Vectorized calculation of $n = Wp + b$ and $a = \text{hardlim}(n)$.
                  * `train_step(self, p, t)`: Process a single input vector, compute error $e = t - a$, apply Hagan's update rule, and return step diagnostics (`p`, `t`, `a`, `e`, `W`, `b`, and whether an update occurred).
                  * `train_epoch(self, P, T)`: Iterate through all training points once in sequence and return the history of updates.
                  * `fit(self, P, T, max_epochs=100)`: Train until complete convergence (error $= 0$ for all samples) or max epochs reached. Record snapshot states (weights, bias, accuracy) at every step/epoch so the frontend can animate the line adapting.


                  * Include rich, clear Python docstrings and comments explaining every single matrix operation.

                  #### 2. `app.py`

                  * Implement a lightweight Flask backend.
                  * Define endpoints:
                  * `GET /`: Serve `index.html`.
                  * `POST /api/train`: Accept JSON payload containing training points `[{"p1": float, "p2": float, "target": int}, ...]`. Return step-by-step weight/bias history, convergence status, total epochs, and final decision boundary parameters.
                  * `POST /api/predict`: Accept arbitrary point $(p_1, p_2)$ and return the predicted class (`Pass` or `Fail`) and net input value $n$.


                  * Include error handling for empty datasets, single-class datasets, and non-separable cases.

                  #### 3. Frontend (`templates/index.html`, `static/style.css`, `static/script.js`)

                  * **Interactive Canvas (HCI Focused):**
                  * An HTML5 Canvas displaying a Cartesian plane with both axes scaled from $0$ to $10$ (X-axis: Study Hours, Y-axis: Attendance / 10).
                  * Grid lines, tick marks, and axis titles clearly rendered.
                  * Left-click on canvas adds a **Passing Student** (Green circle).
                  * Mode toggle switch (or Right-click) adds a **Failing Student** (Red circle).
                  * Ability to click a button to load presets: "Clearly Separable", "Boundary Edge Case", and "Linearly Inseparable (XOR-like fail case)".


                  * **Dynamic Visualization:**
                  * The decision boundary line must update smoothly on the canvas.
                  * Draw the normal weight vector arrow $\mathbf{w}$ originating from the boundary pointing toward the positive region ($a = 1$).
                  * Lightly shade the passing region ($n \ge 0$).


                  * **Controls & Step-by-Step Training:**
                  * Buttons: `Add Preset Data`, `Train (Animated)`, `Step 1 Iteration`, `Reset`.
                  * Speed slider for animation playback.
                  * Live Mathematical Telemetry Panel: Displays current $W = [w_1, w_2]$, Bias $b$, Active Point $p$, Current Error $e$, and Net Input $n$.


                  * **In-App Non-Technical User Guidance (HCI Principles):**
                  * Prominent "How to Play" ribbon at the top with a 3-step visual instruction:
                  1. Click the canvas to place students.
                  2. Click 'Train' to see the AI learn.
                  3. Observe how the line moves to separate Green from Red.


                  * Live status badges explaining what the model is doing in plain English (e.g., *"Student studied 8 hrs but failed? Adjusting boundary downwards..."*).



                  #### 4. `report.md`

                  Must be comprehensive, fully formatted in Markdown, and structured into the following four distinct sections:

                  1. **Title and Problem Overview:**
                  * Formal title and introduction to the Student Exam Pass/Fail prediction problem.
                  * Justification of why a 2D perceptron with hard-limit activation is mathematically suitable.


                  2. **Deep-Dive Algorithm Description (Hagan Chapter 4):**
                  * The origin and mechanics of the single-neuron Perceptron with hardlim transfer function.
                  * Comprehensive explanation of inputs, weights, bias, net input, and step-function output.
                  * The unified update rule derivation ($e = t - a$, $W^{\text{new}} = W^{\text{old}} + ep^T$, $b^{\text{new}} = b^{\text{old}} + e$).
                  * Proof of convergence intuition: upper and lower bounds on $\|x(k)\|^2$ and why it converges in finite steps for linearly separable data.
                  * Walkthrough of every Python function from `perceptron.py` with embedded code snippets, plain-English translations, and line-by-line commentary so a beginner can understand it.


                  3. **Full-Stack Web Architecture & Engineering Guide:**
                  * Architecture diagram/flow: Browser Canvas $\leftrightarrow$ JavaScript Event Loop $\leftrightarrow$ JSON API $\leftrightarrow$ Flask $\leftrightarrow$ NumPy Perceptron.
                  * Explanation of coordinate transformation: Mapping DOM canvas pixel space $(x, y)$ to mathematical feature space $(p_1, p_2) \in [0, 10]^2$.
                  * Breakdown of the API contract, request/response formats, and core client-side rendering functions.


                  4. **10-Year-Old & Non-Technical User Manual:**
                  * Analogy-driven explanation (e.g., "The teacher drawing a chalk line on the floor").
                  * Clear explanation of inputs (study time, class attendance) and outputs (pass/fail).
                  * What the moving line actually means in real life.
                  * Step-by-step usage guide with troubleshooting (e.g., "What if the line never stops spinning?" explaining linear inseparability without jargon).



                  ---

                  ### Execution Directive

                  Deliver every file in full sequence. Ensure the code is modular, modern, clean, fully commented, and directly copy-pasteable so the application can be run immediately with `python app.py`.

```
